## Affected Routes
- GET /api/v1/seat-track-record?skill=<skill_path> — 404 unknown skill; 200 with {seat, track_record}; avg_rating reflects ratings
- POST /api/v1/ratings — {skill, rating[, task_id, model]} → appends a 'rating' seat_event; 400 on missing skill/rating

## Key Interactions to Verify
- Two runs of the same skill resolve the SAME seat_id; runs count 1 -> 2 (identity persists)
- get_track_record aggregates in SQL (runs/success_rate/gate_pass_rate/avg_cost/avg_latency/avg_rating); empty seat -> zeros, no divide-by-zero
- current_model preserved when a later resolve passes empty model (COALESCE regression)

## Edge Cases
- SeatStore/DB down -> resolve_seat/record_outcome/record_rating never raise; run outcome byte-identical
- DB tests use uuid-suffixed seat names (append-only ledger, shared Postgres — no cross-run accumulation)
- rename_seat NOT exercised in v1 pipeline path (roadmap-only; would orphan history if called)

## Critical Paths
- Pipeline step -> resolve seat once -> bind fleet_agents.seat_id -> record_outcome on completion -> track record readable by skill
